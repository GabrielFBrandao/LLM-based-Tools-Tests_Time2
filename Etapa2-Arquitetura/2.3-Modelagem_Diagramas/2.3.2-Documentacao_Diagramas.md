### 1.7 Fluxo de Dados Completo

**Exemplo: Criar Reserva**

```
1. FRONTEND (Apresentação)
   ├─ Usuario preenche formulário ReservaCadastroForm
   ├─ Validação client-side (campos obrigatórios, datas)
   └─ React Query executa useCriarReserva()
        └─ POST /api/reservas { quartoId, hospedeId, ... }

2. BACKEND - CONTROLLER (Aplicação)
   ├─ ReservasController.criarReserva() recebe requisição
   ├─ ValidationPipe valida CriarReservaDto
   │   ├─ @IsUUID() quartoId
   │   ├─ @IsUUID() hospedeId
   │   └─ @IsDate() dataCheckIn, dataCheckOut
   └─ Delega para ReservasService.criarReserva(dto)

3. SERVICE (Domínio)
   ├─ ReservasService.criarReserva()
   ├─ Inicia transação Prisma ($transaction)
   │   ├─ validarDisponibilidadeQuarto(quartoId)
   │   │   └─ QuartosService.buscarPorId(quartoId)
   │   │       └─ IQuartosRepository.findById()
   │   │           └─ PrismaQuartosRepository
   │   ├─ IReservasRepository.create(reserva)
   │   │   └─ PrismaReservasRepository
   │   │       └─ prisma.reserva.create()
   │   ├─ QuartosService.alterarStatus(quartoId, 'OCUPADO')
   │   │   └─ IQuartosRepository.updateStatus()
   │   │       └─ prisma.quarto.update()
   │   └─ COMMIT (ou ROLLBACK se erro)
   └─ Logger.info('Reserva criada', { reservaId, quartoId })

4. PERSISTÊNCIA
   ├─ PostgreSQL executa queries dentro de transação:
   │   ├─ SELECT * FROM quartos WHERE id = $1
   │   ├─ INSERT INTO reservas (...)
   │   └─ UPDATE quartos SET status = 'OCUPADO' WHERE id = $1
   └─ COMMIT

5. RESPOSTA
   ├─ SERVICE retorna Reserva criada
   ├─ CONTROLLER retorna 201 Created
   └─ FRONTEND
       ├─ React Query invalida cache de reservas e quartos
       ├─ Atualiza listagens automaticamente
       └─ Exibe toast de sucesso
```

### 1.8 Comunicação Entre Camadas

| De → Para | Protocolo | Descrição |
|-----------|-----------|-----------|
| Frontend → Backend | HTTP REST | Axios/Fetch via React Query |
| Controller → Service | Method Call | Dependency Injection (NestJS) |
| Service → Repository | Interface Call | Repository Pattern (desacoplado) |
| Repository → Prisma | ORM API | Prisma Client (type-safe) |
| Prisma → PostgreSQL | SQL | Queries parametrizadas |

**Princípios:**
- **Unidirecional**: Camadas superiores não conhecem inferiores
- **Dependency Inversion**: Dependências apontam para abstrações (interfaces)
- **Separation of Concerns**: Cada camada tem responsabilidade única

### 2.4 Value Objects

Value Objects são objetos **imutáveis** que encapsulam validações e comportamentos específicos. Seguem o princípio DDD de não ter identidade própria — dois value objects com o mesmo valor são considerados iguais.

- `equals(outro: CPF): boolean` — Compara dois CPFs

**Vantagens:**
- Garante que apenas CPFs válidos existam no sistema
- Centraliza lógica de validação (não espalha pelo código)
- Imutável: previne alterações acidentais

**Algoritmo de Validação:**
```typescript

// 2. Verificar se não é sequência repetida (ex: 111.111.111-11)
// 3. Calcular primeiro dígito verificador
// 4. Calcular segundo dígito verificador
// 5. Comparar com os dígitos informados
```

```typescript
async cadastrarQuarto(dto: CadastrarQuartoDto): Promise<Quarto> {
  // 1. Validar número único
  if (await this.validarNumeroUnico(dto.numero)) {
    throw new ConflictException('Número de quarto já existe');
  }
  
  // 2. Validar capacidade e preço
  if (!this.validarCapacidade(dto.capacidade)) {
    throw new BadRequestException('Capacidade deve ser maior que zero');
  }
  
  if (!this.validarPreco(dto.precoDiaria)) {
    throw new BadRequestException('Preço deve ser maior que zero');
  }
  
  // 3. Criar quarto com status LIVRE
  const quarto = new Quarto({ ...dto, status: StatusQuarto.LIVRE });
  
  // 4. Adicionar camas
  dto.tiposCama.forEach(tipo => quarto.adicionarCama(tipo));
  
  // 5. Persistir
  return await this.repository.create(quarto);
}
```

```typescript
async alterarStatus(id: string, status: StatusQuarto): Promise<Quarto> {
  const quarto = await this.repository.findById(id);
  
  if (!quarto) {
    throw new NotFoundException('Quarto não encontrado');

  // Validar se pode alterar status
  // Ex: Se tem reserva ativa, não pode mudar para LIVRE manualmente
  
  return await this.repository.updateStatus(id, status);
```

#### 2.6.3 ReservasService

**Dependências:**
- `IReservasRepository` (injetado)
- `QuartosService` (injetado)

**Método Principal: Criar Reserva com Transação ACID (ADR-007)**

```typescript
async criarReserva(dto: CriarReservaDto): Promise<Reserva> {
  return await this.prisma.$transaction(async (tx) => {
    
    // 1. Validar disponibilidade do quarto DENTRO DA TRANSAÇÃO
    const quarto = await this.quartosService.buscarPorId(dto.quartoId);
    
    if (!quarto) {
      throw new NotFoundException('Quarto não encontrado');
    }
    
    if (!quarto.isDisponivel()) {
      throw new ConflictException('Quarto indisponível para reserva');
    }
    
    // 2. Calcular valor total
    const valorTotal = await this.calcularValorTotal(
      dto.quartoId,
      dto.dataCheckIn,
      dto.dataCheckOut
    );
    
    // 3. Criar reserva
    const reserva = new Reserva({
      ...dto,
      status: StatusReserva.ATIVA,
      valorTotal
    });
    
    const reservaCriada = await this.repository.create(reserva);
    
    // 4. Atualizar status do quarto para OCUPADO
    await this.quartosService.alterarStatus(
      dto.quartoId,
      StatusQuarto.OCUPADO
    );
    
    // 5. Registrar log
    this.logger.info('Reserva criada com sucesso', {
      reservaId: reservaCriada.id,
      quartoId: dto.quartoId,
      hospedeId: dto.hospedeId
    });
    
    // Se qualquer etapa falhar, ROLLBACK automático
    return reservaCriada;
  });
}
```

**Método: Cancelar Reserva com Transação ACID**

```typescript
async cancelarReserva(id: string): Promise<void> {
  return await this.prisma.$transaction(async (tx) => {
    
    // 1. Buscar reserva
    const reserva = await this.repository.findById(id);
    
    if (!reserva) {
      throw new NotFoundException('Reserva não encontrada');
    }
    
    if (reserva.isCancelada()) {
      throw new ConflictException('Reserva já está cancelada');
    }
    
    // 2. Cancelar reserva
    await this.repository.cancelar(id);
    
    // 3. Liberar quarto (status LIVRE)
    await this.quartosService.alterarStatus(
      reserva.quartoId,
      StatusQuarto.LIVRE
    );
    
    // 4. Registrar log
    this.logger.info('Reserva cancelada com sucesso', {
      reservaId: id,
      quartoId: reserva.quartoId
    });
    
    // ROLLBACK automático se falhar
  });
}
```

**Métodos Privados:**
- `validarDisponibilidadeQuarto(quartoId: string): Promise<boolean>`
- `atualizarStatusQuarto(quartoId: string, status: StatusQuarto): Promise<void>`

### 2.8 Relacionamentos Entre Classes

**Composição (◆):**
- `Quarto` ◆—→ `QuartoCama`
  - QuartoCama não existe independentemente de Quarto
  - Se Quarto for deletado, suas camas também são deletadas

**Agregação (◇):**
- `Quarto` ◇—→ `Reserva`
- `Hospede` ◇—→ `Reserva`
  - Reserva referencia Quarto e Hospede, mas não os "possui"
  - Deletar Reserva não deleta Quarto nem Hospede

**Uso (---→):**
- `Quarto` ---→ `TipoQuarto`, `StatusQuarto`, `Dinheiro`
- `Hospede` ---→ `CPF`, `Email`
- `Reserva` ---→ `StatusReserva`, `Dinheiro`

**Dependência (..>):**
- `QuartosService` ..> `CadastrarQuartoDto`
- `QuartosService` ---→ `IQuartosRepository`
- `ReservasService` ---→ `QuartosService`

## 3. PADRÕES DE PROJETO APLICADOS

### 3.1 Repository Pattern (ADR-005)

**Objetivo:** Abstrair a camada de persistência.

**Implementação:**
- Interfaces: `IQuartosRepository`, `IHospedesRepository`, `IReservasRepository`
- Implementações concretas: `PrismaQuartosRepository`, etc.
- Services dependem apenas das interfaces (Dependency Inversion)

**Benefícios:**
- Services desacoplados do Prisma
- Fácil substituição de ORM
- Testabilidade via mock

---

### 3.2 Dependency Injection

**Objetivo:** Inverter controle de dependências.

**Implementação:** NestJS gerencia DI automaticamente

```typescript
@Injectable()
export class QuartosService {
  constructor(
    @Inject('IQuartosRepository')
    private readonly repository: IQuartosRepository
  ) {}
}
```

---

### 3.3 Data Transfer Object (DTO)

**Objetivo:** Transferir dados entre camadas de forma segura e validada.

**Implementação:** Classes com decorators de validação (class-validator)

**Benefícios:**
- Validação automática
- Contratos explícitos
- Não expõe entidades diretamente

---

### 3.4 Value Object Pattern

**Objetivo:** Encapsular validações e comportamentos em objetos imutáveis.

**Implementação:** Classes CPF, Email, Dinheiro

**Benefícios:**
- Validação centralizada
- Imutabilidade
- Type safety

---

### 3.5 Transaction Script com ACID (ADR-007)

**Objetivo:** Garantir consistência em operações críticas.

**Implementação:** Prisma `$transaction` API

```typescript
await this.prisma.$transaction(async (tx) => {
  // Operações atômicas
  // ROLLBACK automático se falhar
});
```

**Benefícios:**
- Atomicidade
- Consistência
- Isolamento
- Durabilidade
