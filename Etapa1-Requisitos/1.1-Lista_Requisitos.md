# Input:

> "Liste requisitos funcionais (RF) e não funcionais (RNF) para este sistema."

---

# Output:

## 1. Requisitos Funcionais (RF)

### Módulo: Gestão de Quartos
* **RF01** - O sistema deve permitir o cadastro de quartos com os campos: número do quarto, capacidade, tipo (Básico, Moderno, Luxo), preço por diária, frigobar, café da manhã incluso, ar-condicionado e TV.
* **RF02** - O sistema deve permitir o cadastro de tipos de cama para cada quarto (Solteiro, Casal King, Casal Queen).
* **RF03** - O sistema deve permitir a edição de informações de quartos cadastrados.
* **RF04** - O sistema deve listar todos os quartos cadastrados exibindo: número do quarto, tipo, preço por diária e disponibilidade.
* **RF05** - O sistema deve permitir a alteração do status de disponibilidade do quarto (Ocupado, Livre, Manutenção, Limpeza).
* **RF06** - O sistema deve validar que o número do quarto seja único no cadastro.

### Módulo: Gestão de Hóspedes
* **RF07** - O sistema deve permitir o cadastro de hóspedes com os campos: nome, sobrenome, CPF e email.
* **RF08** - O sistema deve listar todos os hóspedes cadastrados exibindo: nome, sobrenome e CPF.
* **RF09** - O sistema deve validar o formato do CPF no cadastro de hóspedes.
* **RF10** - O sistema deve validar o formato do email no cadastro de hóspedes.
* **RF11** - O sistema deve garantir que o CPF seja único no sistema (não permitir duplicação).

### Módulo: Gestão de Reservas
* **RF12** - O sistema deve permitir a criação de reservas associando um hóspede a um quarto.
* **RF13** - O sistema deve listar todas as reservas exibindo: número do quarto, tipo do quarto, nome do hóspede e disponibilidade.
* **RF14** - O sistema deve permitir a edição de reservas existentes.
* **RF15** - O sistema deve atualizar automaticamente o status do quarto para "Ocupado" ao criar uma reserva.
* **RF16** - O sistema deve permitir o cancelamento de reservas.
* **RF17** - O sistema deve atualizar o status do quarto para "Livre" ao cancelar uma reserva.
* **RF18** - O sistema deve impedir a criação de reservas para quartos com status "Manutenção" ou "Limpeza".

## 2. Requisitos Não Funcionais (RNF)

### Usabilidade
* **RNF01** - A interface do sistema deve utilizar paleta de cores verde e azul.
* **RNF02** - O sistema deve utilizar componentes modernos e responsivos para interface web.
* **RNF03** - O sistema deve exibir mensagens de feedback claras para ações do usuário (sucesso, erro, validação).
* **RNF04** - O sistema deve ser responsivo, adaptando-se a diferentes tamanhos de tela (desktop, tablet, mobile).
* **RNF05** - O sistema deve seguir princípios de UX/UI para facilitar a navegação intuitiva.

### Desempenho
* **RNF06** - O sistema deve carregar as listagens em até 2 segundos.
* **RNF07** - O sistema deve processar operações de cadastro e edição em até 1 segundo.

### Segurança
* **RNF08** - O sistema deve validar todos os dados de entrada para prevenir injeção de código.
* **RNF09** - O sistema deve implementar autenticação de usuários (futura implementação).
* **RNF10** - O sistema deve registrar logs de todas as operações críticas (criação, edição, exclusão).

### Confiabilidade
* **RNF11** - O sistema deve garantir a integridade dos dados em caso de falhas.
* **RNF12** - O sistema deve ter disponibilidade de 99% durante o horário comercial.

### Manutenibilidade
* **RNF13** - O código do sistema deve seguir padrões de clean code e boas práticas.
* **RNF14** - O sistema deve ser modular, permitindo fácil manutenção e expansão.
* **RNF15** - O sistema deve possuir documentação técnica atualizada.

### Portabilidade
* **RNF16** - O sistema deve ser compatível com os principais navegadores (Chrome, Firefox, Safari, Edge).
